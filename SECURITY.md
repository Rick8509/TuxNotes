# Security policy

TuxNotes stores private notes, encrypts locked notes and backups, and holds a Google Drive sign-in, so security reports are very welcome.

## Supported versions

Security fixes go into the newest release. Please update to the [latest release](https://github.com/Rick8509/TuxNotes/releases/latest) before reporting.

## Reporting a problem

**Please don't open a public issue.** Report it privately instead:

1. Go to the [Security tab](https://github.com/Rick8509/TuxNotes/security) of this repository.
2. Click **Report a vulnerability** and describe the problem.

Helpful details: the TuxNotes version, your Linux distribution, the steps to reproduce, and what an attacker could do. Never include real notes, passwords or tokens.

You'll get an answer as soon as possible, usually within a week. Once a fix is released, the report is published as a security advisory, with credit to you if you'd like.

## Scope

Examples of what counts: reading locked notes or encrypted backups without the password, weaknesses in the encryption, leaking the Google sign-in, attachments or imported files writing outside TuxNotes' folders, and content in a note running code.
